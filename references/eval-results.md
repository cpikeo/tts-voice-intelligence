# 评测方法与实测结果

所有数字来自 `tests/run_eval.py` 的真实运行（输出目录：`summary.json` / `summary.md`）。未做人工听评，结论仅为客观代理指标。

## 1. 环境

- Debian 13，Python 3.13，2 vCPU，1.9 GB 内存，无 GPU，无 ffmpeg
- piper-tts 1.8.0，onnxruntime（CPU）
- 回听识别：faster-whisper 1.2.1 + whisper `small`（int8，CPU），中文输出经 OpenCC `t2s` 转简体后比较
- 评测集：`tests/cases.jsonl`，9 条，覆盖短文本、普通中文、长文本、日期与时刻、百分比、中英混合、专有名词、多音字、停顿与标点

## 2. 指标定义

| 指标 | 含义 | 判定 |
|---|---|---|
| 信号层（fail/warn） | 可解码、削波、NaN、直流、峰值、有声 RMS、内部长静音、静音区爆点、时长 | 见 `scripts/qa.py`；阈值为经验值 |
| `norm_cer` | 规范化后的原文 vs 回听文本的字符错误率（去除标点与空白） | 越低越好 |
| `raw_cer` | 原文不做规范化直接合成后的 CER（同一回听流程） | 用于衡量规范化的作用 |
| RTF | 合成耗时 / 音频时长（不含回听） | 越低越快 |

**CER 的局限**：参考文本是“规范化 + 发音词典”之后的朗读形式，所以它衡量的是“引擎是否按朗读形式读出”，**不能证明朗读形式本身是正确读法**（例如词典里“派森”是否为用户期望的读音，需要用户确认）。回听模型本身也会犯错，尤其是专名与英文。

## 3. 结果（最终代码，同一次运行）

### huayan（`zh_CN-huayan-medium`）

|---|---|---|---|---|
| zh_short | 短文本 | 0.0 | 0.0 | 0.081 |
| zh_plain | 普通中文 | 0.0625 | 0.0625 | 0.081 |
| zh_long | 长文本 | 0.16 | 0.0933 | 0.072 |
| digits_date | 数字日期 | 0.0938 | 0.2188 | 0.089 |
| percent | 百分比 | 0.1481 | 0.0741 | 0.073 |
| mixed_en | 中英混合 | 0.2903 | 0.5484 | 0.081 |
| proper | 专有名词 | 0.24 | 0.24 | 0.074 |
| polyphone | 多音字 | 0.2 | 0.1 | 0.089 |
| punct_pause | 停顿与标点 | 0.2083 | 0.1667 | 0.083 |

均值：规范化 **0.156**，原文直送 0.167。信号层：9 条全部无 fail/warn。

### xiao_ya（`zh_CN-xiao_ya-medium`）

| 用例 | 类别 | CER（规范化） | CER（原文直送） | RTF |
|---|---|---|---|---|
| zh_short | 短文本 | 0.0 | 0.0 | 1.131（首条含冷启动） |
| zh_plain | 普通中文 | 0.0 | 0.0 | 0.127 |
| zh_long | 长文本 | 0.0267 | 0.04 | 0.099 |
| digits_date | 数字日期 | 0.0312 | 0.125 | 0.086 |
| percent | 百分比 | 0.0 | 0.0 | 0.122 |
| mixed_en | 中英混合 | 0.2258 | 0.3548 | 0.139 |
| proper | 专有名词 | 0.2 | 0.28 | 0.127 |
| polyphone | 多音字 | 0.0 | 0.0 | 0.150 |
| punct_pause | 停顿与标点 | 0.0 | 0.0 | 0.108 |

均值：规范化 **0.054**，原文直送 0.089。信号层：9 条全部无 fail/warn。

词典（`assets/lexicon.example.tsv`）两模型均启用。

## 4. 关键结论

1. **文本规范化有效**：数字/日期/百分比类用例两模型的 CER 均显著下降（huayan 0.219→0.094，xiao_ya 0.125→0.031）。
2. **例外**：huayan 的百分比用例规范化后反而变差（0.074→0.148），回听显示模型对“百分之三点五”的识别偏离。这是单条用例、单次运行的结果，不能下过强结论，但说明规范化不是万能的。
3. **英文与专名仍是最弱项**：两模型的中英混合与专名 CER 都在 0.2–0.3 区间，明显高于中文用例。词典能改善（见第 5 节），但不能根除。
4. **多音字证据有限**：多音字用例仅 1 条。xiao_ya 为 0，huayan 为 0.2。
5. **音频信号层稳定**：36 个音频文件（2 模型 × 9 条 × 规范化开/关）的信号层检查全部通过；有声 RMS 在 -20.15 至 -20.51 dBFS 之间（目标 -20），无削波，无直流偏移。
   - 注：评测过程中发现点击检测器存在假阴性（永远输出 0），已修正并加入回归测试（注入爆点检出 1 次、干净正弦音 0 次），修正后重新核验了上述 36 个文件，结论不变。点击检测仍属启发式，未在真实听感数据上标定。

## 6. 重复性与波动

同一配置、同一代码，两次完整运行（第 3 节与更早的一次）：

- huayan 规范化 CER：逐条最大差 0.08，平均差 0.03；均值 0.151 vs 0.156
- xiao_ya 规范化 CER：逐条最大差 0.065，平均差 0.012；均值 0.042 vs 0.054

因此，**单条用例 CER 差 < 0.1 不具有统计意义**。判断改进时应至少重复 2–3 次并看均值。

## 7. 未覆盖与已知限制

- 无人工听评（MOS）。自然度、表现力、情绪、音色一致性**均未经人工评估**，不能宣称已达到某个主观质量水平。
- 评测规模：9 条、1 个回听模型（whisper-small）、2 个中文模型。不代表所有文本类型。
- 长文本连续性：仅测了一条约 60 字的长文本；未测 >10 分钟的文本，未测跨任务声音一致性。
- 未测 GPU（无 GPU 环境），未测 `--noise-scale 0` 的听感。
- 未测 MP3 输出（不支持）。
- 回听识别可能将正确发音误判为错误（尤其英文），CER 应与人工抽听一起看。

## 8. 复现

```bash
# 安装见 references/engines.md
python tests/run_eval.py --model MODEL.onnx --out OUT_DIR --asr small --lexicon assets/lexicon.example.tsv
```

输出 `OUT_DIR/summary.md` 与 `summary.json`。注意：每次运行的音频不逐字节相同（见 engines.md 的随机性说明）。
