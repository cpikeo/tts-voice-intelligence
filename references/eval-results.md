# 评测方法与实测结果

所有数字来自 `tests/run_eval.py` 的真实运行（输出 `summary.json` / `summary.md`）。
**未做人工听评**：以下结论只覆盖客观代理指标，不能代表自然度、表现力、音色一致性。

## 1. 环境

- Debian 13，Python 3.13，2 vCPU / 2 GB 内存，无 GPU，无 ffmpeg
- piper-tts（Piper 1.8.0），onnxruntime CPU
- 回听：faster-whisper 1.2.1 + whisper `small`（int8，CPU），中文输出经 OpenCC `t2s` 转简体后比较
- 模型：`zh_CN-huayan-medium`（22050 Hz）、`zh_CN-xiao_ya-medium`（22050 Hz）
- 评测集：`tests/cases.jsonl`，9 条；每条每只手臂重复 3 次
- 词典：`assets/lexicon.example.tsv`（5 条），除词典消融实验外全程启用

## 2. 指标定义与各自的适用边界

| 指标 | 含义 | 能证明什么 | **不能**证明什么 |
|---|---|---|---|
| 信号层（fail/warn） | 可解码、削波、NaN、直流、峰值、有声 RMS、内部长静音、静音区爆点、时长 | 文件技术层面可交付 | 任何听感问题 |
| `asr_cer` | 朗读形式参考文本 vs 回听文本的 CER（去标点） | 综合发音清晰度 | **数字读法**：whisper 会把听到的中文数字写成阿拉伯数字，比对时必须读回中文，因此无法区分“读法对”和“数字串对” |
| `asr_cer_text` | 参考与回听两侧**用同一规则遮蔽数词后**的 CER | 非数字部分的发音，不受规范化链路影响 | 数字读法（被有意遮蔽了） |
| `asr_num_cer` | 仅数词部分的 CER | 听到的数字串是否与朗读形式一致 | **朗读风格**（“2026”读成“二零二六”还是“两千零二十六”，回听都输出 2026） |
| RTF | 合成耗时 / 成品时长 | 速度 | 音质 |

遮蔽规则见 `scripts/textnorm.py` 的 `mask_numbers`。它必须两侧对称，否则 `cer_text` 会系统性偏向某一只手臂。
已知残余不对称：单个中文数字（如“负五”的“五”）不遮蔽，以免误伤“一起”“第一”这类普通词。

## 4. 重复性与噪声下限（决定哪些结论能下）

**用“规范化不改变文本”的用例做零效应对照**——这些用例两只手臂送进引擎的文本完全相同，
任何差异都是噪声：

| 模型 | 3 次均值之间的最大偏差 | 平均偏差 | 单条单次运行的极差 |
|---|---|---|---|
| huayan | 0.095 | 0.031 | 最高 0.200 |
| xiao_ya | 0.028 | 0.012 | 最高 0.094 |

对照之下，规范化**确实改变文本**的用例（数字日期、百分比、中英混合、专名）平均改善：
huayan +0.068，xiao_ya +0.119。

结论：

1. **xiao_ya 上规范化的作用成立**（效应 0.119 ≫ 噪声 0.028）。
2. **huayan 上只能在单条用例层面下结论**：整体效应 0.068 与噪声上限 0.095 同量级；
   只有 `digits_date`（+0.125）与 `mixed_en`（+0.097）超过噪声，可以单独采信。
3. **单次运行的 CER 不能用于判断改进**。单条极差最高 0.200（huayan 多音字用例）。
   判断任何改进都要重复 ≥3 次并比较均值。
4. `qa.py --profile strict`（0.05）**低于实测噪声水平**，只在多次重复取均值后使用；
   `default`（warn 0.10 / fail 0.25）与“人工可接受”粗略对齐，仍是经验值，不是行业标准。
5. 旧版文档曾记载“huayan 百分比用例规范化后变差（0.074→0.148）”。重复测量后方向相反
   （0.123 vs 0.173，规范化更好）。**这正是旧结论只跑了一次造成的**。

## 5. 发音词典的效果（受控消融，3 次重复均值，规范化手臂）

只有“是否加载词典”这一个变量不同：

| 模型 | 用例 | 无词典 CER | 有词典 CER | 改善 |
|---|---|---|---|---|
| huayan | mixed_en | 0.476 | 0.409 | 0.068 |
| huayan | proper | 0.344 | 0.173 | 0.171 |
| xiao_ya | mixed_en | 0.371 | 0.118 | 0.253 |
| xiao_ya | proper | 0.444 | 0.187 | 0.258 |

英文与专名仍是两个模型的最弱项。**词典给出的是“朗读形式”，其正确性必须由用户或业务方确认**——
CER 低只能说明“引擎按词典读了”，不能说明“词典里的读法是用户要的”。

## 6. 客观一致性（长文本）

`tts.py` 报告中的 `segment_rms_std_db`（各段对齐后有声 RMS 的标准差，客观代理）：

- 972 字中文、36 段、成品 187 秒：`segment_rms_std_db` = 0.072 dB，峰值 -1.0 dBFS，无 fail。
- 这是**响度一致性**，不等于音色一致性；后者需要人工听评。

## 7. 未覆盖与已知限制

- **无人工听评**。自然度、表现力、情绪、音色一致性、段间连续性**均未经人工评估**。
  工具 `scripts/blindtest.py` 已就绪并可复现，但本仓库尚未采集任何人类评分。
- 评测规模：9 条用例、1 个回听模型（whisper-small）、2 个中文模型。不代表所有文本类型。
- 长文本：最长约 972 字；未测 >10 分钟的文本，未测跨任务的声音一致性。
- 未测 GPU（无 GPU 环境）；`--noise-scale 0` 的可复现性已验证，但**听感未评估**。
- 未测 MP3 输出（不支持）；OGG 只验证过可写与可解码，未做听感验证。
- 资源边界：2 GB 环境下 xiao_ya（g2pW 前端）与 whisper-small 同时驻留会 OOM（exit 137）。
  `run_eval.py` 因此分两阶段执行；更小内存请用 `--asr base`。
- 回听本身会犯错，尤其英文与专名，CER 应与人工抽听一起看。

## 8. 复现

```bash
# 安装见 references/engines.md
python tests/run_eval.py --model MODEL.onnx --out OUT_DIR \
  --asr small --lexicon assets/lexicon.example.tsv --repeat 3
```

输出 `OUT_DIR/summary.md` 与 `summary.json`（含模型 sha256、峰值 RSS、每次重复的原始值）。
注意：每次运行的音频不逐字节相同（见 `engines.md` 的随机性说明），因此 CER 必须重复测量。
