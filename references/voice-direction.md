# 声音导演手册

用于 `SKILL.md` 第 2 步“制定声音策略”。这里的规则是**启发式起点**，不是已通过听评验证的定论；每条都标注了验证状态。

## 1. 先问四件事

1. **谁在说**：角色/品牌气质（旁白、客服、讲解、故事角色）。单说话人 Piper 模型只能提供一种音色，不要承诺“换成另一个人”。
2. **对谁说**：听众与场合（新闻播报 / 课程 / 助手应答 / 有声书）。
3. **说多久**：短提示音（<10 秒）与长文本（>1 分钟）的一致性要求不同。
4. **有没有硬性要求**：必须准确的专名、数字、日期；必须符合的时长；必须可商用的授权。

用户未说明时，按场景默认值执行，并在交付说明中写明假设。仅在关键信息（如商用授权）缺失且会改变结论时才询问用户。

## 2. 场景 → 参数起点

| 场景 | `--length-scale` | 段落停顿 ms | 句间停顿 ms | 子句停顿 ms | 备注 |
|---|---|---|---|---|---|
| 新闻/通知播报 | 1.0 | 650 | 350 | 180 | 节奏稳，少停顿 |
| 课程讲解 | 1.1 | 800 | 450 | 220 | 略慢，给听众消化时间 |
| 故事/有声书/旁白 | 1.15 | 950 | 500 | 250 | 句间留白，允许长停顿 |
| 短提示/按钮语音 | 1.0 | — | — | — | 整段一句，不分段 |

数值取整即可：这些是**未经听评校准的起点**，精确到个位数没有依据（此前写成 600–700、150–200 这类区间，是伪精度）。
调整时只改一个参数，合成后用 QA 与人工试听对比。旁白介于讲解与故事之间，按文本的叙事性强弱取两者之一。

## 3. 文本准备（引擎前端最容易出错的地方）

规范化由 `scripts/textnorm.py` 自动完成，但以下情况需要人工判断：

**自动处理（无需人工）**：

- 日期 `2026/10/12`、`2026-10-12` → “二零二六年十月十二日”
- 年份 `2026年` → 逐位读“二零二六年”
- 时刻 `10:30` → “十点三十分”；`10:00` → “十点整”
- 百分比 `3.5%` → “百分之三点五”
- 亿/万 单位 `1亿2000万` → “一亿二千万”
- 亿级大数 `100000000` → “一亿”（旧版会逐位读成“一零零零零零零零零”）
- 负号 `-5` → “负五”（范围 `10-20` 不受影响）
- 编号/型号 `A-1024`、`GPT-4` → 数字逐位读
- 版本号 `Python 3.13` → “Python 三点一三”（读法是否符合口语需人工确认）
- 符号 `&`→“和”、`+`→“加”、`…`→“……”；Markdown 残留（`**`、`#`、反引号）会被去除

**必须人工改写**（规范化覆盖不到，直接写进正文会读错）：

- 电话号码、身份证号、银行卡号
- 价格区间与范围（`10-20` 只转成“十-二十”，连字符会成为停顿）
- 比值（`3:2` → “三比二”）、分数、百分比带小数点的口语读法
- 复杂公式、表格、代码、列表符号

**需要人工判断**：

- **英文缩写与专名**（GPU、Python、OpenAI）：中文模型读音常不准。用 `--lexicon` 指定朗读形式（见 `assets/lexicon.example.tsv`）。**词典条目必须由用户或业务方确认读法**，不要替用户臆造品牌读音。词典给出的朗读形式是最终形式，不会被数字规则二次改写。
- **多音字**：没有引擎侧的消歧能力，且不同模型表现不同（见 `eval-results.md`）。若发现误读，用词典或改写词语搭配消歧（如“重庆”写成“重庆市”），不要靠反复重合成碰运气。

## 4. 停顿与分段

- 分段规则：段落 > 句子 > 子句。单句超过 `--max-chars`（默认 90 字）时在逗号、分号、顿号处切分；仍超长则硬切。
- **代价**：每段由引擎独立合成，段与段之间的韵律不连续。因此尽量在自然停顿处切，避免把一个完整的长句切成两半。
- 停顿是后期插入的静音，不是模型生成的停顿。它能保证节奏稳定，但不能替代语义上的重音控制。

## 5. 表现力的边界

- Piper 模型**没有显式情绪控制**。不要承诺“高兴地说”“悲伤地说”。
- 可以间接影响的手段：语速（`--length-scale`）、标点（问号、感叹号、省略号会改变语调）、句长、停顿。
- 这些手段的效果需要人工听评确认，**本 Skill 未对情绪表达做过量化验证**。
- 声音克隆：本 Skill 不做克隆；使用他人声音必须获得所有者书面授权，并遵守模型许可。

## 6. 一致性

- 同一任务的所有段使用**同一模型、同一参数、同一词典**；跨次任务若需要声音一致，应固定这三者，并在报告中记录。
- 响度：流水线对每段有声部分做 RMS 对齐（目标 -20 dBFS，增益限制 ±12 dB），再统一限峰到 -1 dBFS。实测多段输出 RMS 与目标一致（见 eval-results.md）。
- 段间淡入淡出 12 ms，防止爆音；这不是音色处理，若要更强的拼接效果需人工复听。

## 7. 常见问题与对策

| 听感问题 | 可能原因 | 对策 |
|---|---|---|
| 某个英文词读成别的音 | 引擎无英文发音能力 | 加入 `--lexicon` 条目，并用 `qa.py --asr` 复核 |
| 数字读法别扭 | 规范化未覆盖的形式 | 改写原文（如把“1200万”写成“一千二百万”） |
| 句子节奏太快 | 语速或停顿偏小 | 调大 `--length-scale` 或停顿参数 |
| 句尾突然下降 | 引擎对长句的韵律处理 | 拆短句，或在句末补充标点 |
| 段落切换生硬 | 段落停顿太短 | 增大 `--pause-para` |
| 整体偏小/偏大 | 目标响度与播放环境不符 | 调整 `--target-db`（默认 -20） |
